# 本番実行環境

## 調査日

2026-07-31

## PHP

- HTTP実行環境にはPHP 8.5.5を採用する。
- HTTPの実行方式はCGI/FastCGIである。
- CLIでは `/opt/php-8.5.5/bin/php` を明示して実行する。
- CLIの既定PHPは古い版を参照しているため、デプロイ処理では使用しない。

## PHP拡張

次の拡張は、HTTP実行環境とPHP 8.5.5のCLI実行環境の両方で利用できる。

| 拡張 | HTTP | CLI |
| --- | --- | --- |
| `imap` | 利用可 | 利用可 |
| `pdo_mysql` | 利用可 | 利用可 |
| `mbstring` | 利用可 | 利用可 |
| `openssl` | 利用可 | 利用可 |
| `json` | 利用可 | 利用可 |
| `curl` | 利用可 | 利用可 |

HTMLメール内の画像をPDFへ描画するため、PHPの`gd`拡張も必要である。この文書に記録済みの本番確認では`gd`の利用可否を確認していないため、Issue #70のデプロイ前にHTTP実行環境とPHP 8.5.5のCLI実行環境の両方で確認する。

## MySQL

- 本番データベースにはMySQL 5.7系を使用する。

## Composer

- Composer 2系を利用できる。
- 既存の共有ComposerはPHP 8.5.5で非推奨警告が出るため、cadence-xsでは使用および更新をしない。
- cadence-xs専用の非公開ツールディレクトリへ、導入時点のComposer 2系安定版を検証済みチェックサムで配置する。
- Composerは `/opt/php-8.5.5/bin/php` を明示して実行する。
- 本番への依存関係導入には、リポジトリで管理するロックファイルを使用する。

## 配置構成

- ドメインのドキュメントルートは、当該ドメインの `public_html` ディレクトリである。
- アプリ本体、依存関係、設定は、アカウントホーム配下かつドキュメントルート外のcadence-xs専用ディレクトリへ配置する。
- Issue #87後は、既存リポジトリcheckout配下の`cadence-xs/`がサービス本体となる。checkout先・公開先は維持し、既存`.env`の配置と公開フロントコントローラーのリンク先は[READMEの初回切り替え手順](../README.md)に従い利用者が変更する。
- ドキュメントルートには、HTTPで公開するフロントコントローラーと静的ファイルのみを配置する。
- HTTP実行環境に `open_basedir` 制限はなく、ドキュメントルート外のアプリ本体を読み込める。
- ドキュメントルート内から、ドキュメントルート外のPHPファイルへのシンボリックリンク経由でアクセスした場合も、PHPの `__DIR__` は実体側のディレクトリで解決されることを確認済み(確認日: 2026-08-04)。フロントコントローラーのコード変更なしで、アプリ本体のドキュメントルート外配置とドキュメントルート内への公開を両立できる。
- 実際のアカウント名、ドメイン、絶対パス、認証情報はリポジトリへ記録しない。

## Apache

- `.htaccess`を利用できる。
- Rewriteを利用できる。
- `Authorization`ヘッダーは、追加設定なしではPHPへ到達しない。
- `.htaccess`でRewriteによる転送を設定すると、`Authorization`ヘッダーがPHPへ到達する。

## SSHと権限

- SSH接続を利用できる。
- アカウントホーム配下へアプリ本体を配置できる。
- ドキュメントルートへ公開ファイルを配置できる。
- デプロイでは、PHPとComposerの実行パスを明示する。

## 運用上の制約

- `/health`エンドポイントは作成しない。
- メール処理はHTTP経由で実行する。
- 秘密情報をIssue、リポジトリ、デプロイログへ出力しない。
